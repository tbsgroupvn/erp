**PrismaService (prisma.service.ts lines 87-98):**
In the production `$on('query')` handler, change the two threshold values, remove the SQL truncation, add params logging, and add `EXPLAIN` plan output for slow queries.

Use `EXPLAIN` (NOT `EXPLAIN ANALYZE`) because EXPLAIN only shows the query plan without re-executing the query, making it safe for production. EXPLAIN ANALYZE would re-execute the slow query, doubling its cost.

Updated code for the production block (lines 88-98):
```typescript
// In production, only log slow queries (>500ms)
this.$on('query', async (event: Prisma.QueryEvent) => {
  if (event.duration > 5000) {
    this.logger.error(
      `CRITICAL slow query (${event.duration}ms) | SQL: ${event.query} | Params: ${event.params}`,
    );
    // Log EXPLAIN plan for diagnostics (safe: plans only, no re-execution)
    try {
      const plan = await this.$queryRawUnsafe(`EXPLAIN ${event.query}`);
      this.logger.error(`EXPLAIN plan: ${JSON.stringify(plan)}`);
    } catch {
      // EXPLAIN may fail for non-SELECT or parameterized queries — skip silently
    }
  } else if (event.duration > 500) {
    this.logger.warn(
      `Slow query (${event.duration}ms) | SQL: ${event.query} | Params: ${event.params}`,
    );
    try {
      const plan = await this.$queryRawUnsafe(`EXPLAIN ${event.query}`);
      this.logger.warn(`EXPLAIN plan: ${JSON.stringify(plan)}`);
    } catch {
      // EXPLAIN may fail for non-SELECT or parameterized queries — skip silently
    }
  }
});
```

Note: The `EXPLAIN` call is wrapped in try/catch because:
1. Parameterized queries with `$1`, `$2` placeholders cannot be directly EXPLAINed without binding values
2. Non-SELECT statements (INSERT, UPDATE, DELETE) may not support EXPLAIN in all contexts
3. The query event fires after execution, so the EXPLAIN is best-effort diagnostic output

Also update the JSDoc comment on the class (line 21) from `>200ms` to `>500ms`:
Change: `In production, query events are enabled to detect slow queries (>200ms).`
To: `In production, query events are enabled to detect slow queries (>500ms).`
