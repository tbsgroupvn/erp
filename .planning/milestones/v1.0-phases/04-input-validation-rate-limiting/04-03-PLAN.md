   ```typescript

   import { FILE_UPLOAD_LIMITS } from '@common/constants/file-upload.constants';
   ```

   b. On the single-file upload method (e.g., `upload`), change `@UploadedFile()` to:
   ```typescript
   @UploadedFile(new FileValidationPipe({
     maxSizeBytes: FILE_UPLOAD_LIMITS.CMS_MEDIA.maxSizeBytes,
     allowedMimeTypes: [...FILE_UPLOAD_LIMITS.CMS_MEDIA.allowedMimeTypes],
   }))
   file: Express.Multer.File,
   ```

   c. On the multi-file upload method (e.g., `uploadMultiple`), if it uses `@UploadedFiles()`, apply validation in the method body since `FileValidationPipe` handles single files. Add a validation loop at the start:
   ```typescript
   const pipe = new FileValidationPipe({
     maxSizeBytes: FILE_UPLOAD_LIMITS.CMS_MEDIA.maxSizeBytes,
     allowedMimeTypes: [...FILE_UPLOAD_LIMITS.CMS_MEDIA.allowedMimeTypes],
   });
   for (const file of files) {
     pipe.transform(file, { type: 'custom' } as any);
   }
   ```

   d. If the media.service.ts has its own MIME or magic number validation, keep it as defense-in-depth (the pipe validates client-declared MIME, the service validates actual file content). Do NOT remove existing service-level validation.

Drive uses a 2-step presigned URL flow: `requestUpload` (get presigned URL) -> client PUTs to MinIO -> `confirmUpload`. The file NEVER passes through NestJS, so FileValidationPipe cannot be used. Instead, validate declared MIME type and size in the DTOs.

1. **request-upload.dto.ts** -- Tighten validation:

   a. Add imports:
   ```typescript
   import { FILE_UPLOAD_LIMITS } from '@common/constants/file-upload.constants';
   ```

   b. Find the `fileSize` or `size` field. If it has `@Max(524288000)` (500MB), change to:
   ```typescript
   @Max(FILE_UPLOAD_LIMITS.DRIVE.maxSizeBytes)  // 25MB
   ```
   NOTE: If the field uses a plain number, use `@Max(25 * 1024 * 1024)` instead.

   c. Find the `mimeType` or `contentType` field. If it lacks MIME validation, add:
   ```typescript
   @IsIn([...FILE_UPLOAD_LIMITS.DRIVE.allowedMimeTypes])
   ```
   Or if `@IsIn` is already present with a different list, update it to use the DRIVE allowedMimeTypes.

   d. If the DTO has a `fileName` or `originalName` field, add `@SanitizeHtmlStrict()` to prevent XSS via filename.

2. **confirm-upload.dto.ts** -- Add MIME validation if missing:

   a. If the DTO has a `mimeType` or `contentType` field, ensure it also validates against DRIVE allowedMimeTypes (defense-in-depth: confirm the declared type matches what was requested).

   b. If the DTO has a `size` field, add `@Max(25 * 1024 * 1024)` if not already present.

3. **drive.controller.ts** -- Verify no additional changes needed:

   a. Read the controller to confirm `requestUpload` and `confirmUpload` methods use the DTOs above.
   b. The existing `@Throttle` decorators on drive methods are fine (30/min for upload, 20/min for versions) -- do NOT change them.
   c. If the controller has any direct file upload endpoints (using `@UploadedFile()`), apply FileValidationPipe with DRIVE limits. Based on research, Drive uses presigned URLs only, so this is unlikely.

NOTE: Drive's presigned URL flow means we CANNOT do magic number validation (file doesn't pass through NestJS). DTO-level declared MIME/size validation is the best we can do. This is documented as a known limitation (Pitfall 6 in RESEARCH.md).
