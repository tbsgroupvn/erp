    2. Create the listener class ApprovalEscalationListener:
    - Inject PrismaService, EventEmitter2, Logger
    - @OnEvent('approval.escalated') handler:
      a. Receive event with { approvalId, type, referenceId, currentStep, currentStepRole, pendingSince }
      b. Look up escalation target from ESCALATION_ROLE_MAP[currentStepRole]
      c. If no target (already at top or unknown role), log warning and return
      d. Find the current PENDING step: prisma.approvalStep.findFirst({ where: { approvalId, stepNumber: currentStep, status: 'PENDING' } })
      e. If no step found, log warning and return
      f. Reassign the step: prisma.approvalStep.update({ where: { id: step.id }, data: { approverRole: escalationTarget, escalatedFrom: currentStepRole, isOverdue: true } })
      g. Log the escalation action: prisma.approvalActionLog.create({ data: { approvalId, userId: 'SYSTEM', action: 'ESCALATE', comment: `Auto-escalated from ${currentStepRole} to ${escalationTarget} due to SLA breach` } })
      h. Emit 'notification.send' event targeting the new role
      i. Log: `Approval ${approvalId} escalated from ${currentStepRole} to ${escalationTarget}`

    3. Note: The ApprovalAction enum may not have 'ESCALATE'. Check Prisma schema. If it does not exist, use 'DELEGATE' as the action type (closest existing action). Add comment explaining this is an auto-escalation delegation.

    4. Add ApprovalEscalationListener to the approval.module.ts providers array alongside the existing ApprovalSlaListener.
